What is This Framework?

The EU AI Security Mapping Framework is a vendor-neutral practitioner guide that maps EU regulatory requirements to operational security controls for enterprise AI agent deployments.

It addresses a specific problem: organizations deploying AI agents need to understand:

  • What security threats are unique to AI agents (not covered by traditional controls)
  • What multiple EU regulations require for these systems
  • What controls actually mitigate those threats and satisfy those requirements

Key Components

Component Count Description
Threats 10 (AGT-001 to AGT-010) Agent-specific threat patterns not addressed by traditional security controls
Controls 5 (CTL-001 to CTL-005) Recommended security controls designed specifically for AI agent deployments
Regulations 4 EU AI Act, NIS2, DORA, and GDPR mapped to threats and controls

Why Four Regulations?

Organizations deploying AI agents in the EU don't just face the EU AI Act. They face overlapping requirements from multiple regulations. This framework maps all of them so you can implement controls once and satisfy multiple requirements.

Key insight: A single control like CTL-001 (Identity Propagation) can satisfy requirements from EU AI Act Art. 14, GDPR Art. 32, NIS2 Art. 21, and DORA Art. 9 simultaneously. This is the "common-control crosswalk" approach.
Regulation Applies To Why It Matters for AI Agents
EU AI Act AI system providers and deployers Core AI-specific requirements: risk management (Art. 9), human oversight (Art. 14), cybersecurity (Art. 15), record-keeping (Art. 12)
GDPR Anyone processing personal data Agents often process personal data; automated decision-making rights (Art. 22), security of processing (Art. 32), data minimization (Art. 5)
NIS2 Essential and important entities Cybersecurity risk management for critical infrastructure (Art. 21); agents are attack vectors
DORA Financial entities ICT risk management, operational resilience (Art. 6-9); agents in financial services face stricter requirements

Not All Regulations Apply to Everyone

Which regulations matter depends on your organization:

  • All organizations deploying AI agents: EU AI Act + GDPR (if processing personal data)
  • Critical infrastructure (energy, transport, health, etc.): Add NIS2
  • Financial services (banks, insurers, investment firms): Add DORA

Use the "By Regulation" tab to focus on the regulations that apply to your organization.

Understanding Relationship Types

The framework uses relationship indicators to show how strongly a control addresses a threat:

Indicator Meaning
primary This control directly and fundamentally addresses the threat. It's a core defense.
secondary This control provides defense-in-depth. It helps but isn't the primary mitigation.
partial This control partially addresses the threat but has known limitations.

The Five Controls (Quick Reference)

ID Name One-Line Summary
CTL-001 Identity and Authorization Context Propagation Agent acts with user's permissions, not its own broad service account
CTL-002 Tool-Output and Context Provenance Content from tools is tagged as data, not instructions the agent should follow
CTL-003 Action Verification at High-Impact Boundaries High-stakes actions require explicit verification before execution
CTL-004 Authorization-Aware Output Filtering Agent outputs are filtered to only what the user is authorized to see
CTL-005 End-to-End Audit and Accountability Every action is traceable to user, agent, context, and authorization basis

Technical Details

Data Sources

This explorer is built from three JSON data files:

  • data/threats.json — 10 threat definitions with attack scenarios, controls, and regulatory hooks
  • data/controls.json — 5 control specifications with implementation patterns and failure modes
  • data/mappings.json — Relationships between threats, controls, and regulatory requirements

Dependencies

This application has zero external dependencies. It is a single HTML file with:

  • Embedded CSS (no external stylesheets)
  • Embedded JavaScript (no frameworks or libraries)
  • Embedded data (no API calls or external data fetching)

You can download the HTML file and open it locally in any modern browser. No server required.

Rebuilding the Explorer

If the source JSON files are updated, rebuild the explorer with:

# Generate explorer data from source files
python3 scripts/build-explorer.py

# Update the HTML with new data
python3 scripts/update-explorer-html.py

Browser Compatibility

Works in all modern browsers: Chrome, Firefox, Safari, Edge. No IE11 support.

About the Framework

The EU AI Security Mapping Framework is an independent practitioner project. It is:

  • Vendor-neutral — No product recommendations or vendor names in the core framework
  • Practitioner-focused — Written by and for security professionals implementing AI agents
  • Regulation-grounded — Every control traces to specific regulatory articles
  • Honest about gaps — Known limitations and control gaps are documented explicitly

The full practitioner guide is available as a markdown document with detailed implementation guidance, regulatory analysis, and worked examples.
