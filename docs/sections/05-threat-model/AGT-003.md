# AGT-003: Tool-Chain Abuse

**Status**: Compressed draft. Schema-faithful but lighter detail than AGT-001 and AGT-002. Realistic example to be populated.

**Primary surface**: Tool-use
**Secondary surfaces**: Model, Output

## Description

An AI agent invokes multiple individually authorized tools in sequence to achieve an outcome that no single tool would have permitted. Each step in the chain passes its tool-level authorization check; the harm emerges from the composition. Traditional security controls authorize individual actions; agents compose actions in ways the original authorization model did not anticipate. The threat is structural to the agent runtime: it exists wherever tool-level authorization is treated as sufficient for the agent's action authority overall.

Sub-patterns include sequential composition (chained tool invocations producing emergent harm), data-flow chaining (low-sensitivity reads aggregated into high-sensitivity composites), and privilege accumulation across tools (cumulative capability exceeding any single tool's scope). Cross-tool context smuggling and loop-based amplification are related variants.

## Attack scenario

A workflow automation agent in a regulated DACH financial services enterprise has tool authorizations to (a) read individual customer transactions, (b) compute simple aggregations, and (c) write summary reports to a shared workspace. Each tool's authorization is set conservatively at the individual action level. A user requests an analysis of "recent activity patterns for customer Schmidt." The agent reads each transaction individually, computes an aggregation that effectively reconstructs a financial profile, and writes the result to the shared workspace where colleagues can read it. No individual tool call exceeded its authorization, no anomaly was detected at any layer, and the resulting profile constitutes a privacy-sensitive composite that should have required review under DORA Article 6 risk management and GDPR Article 5(1)(c) data minimization. The composition emerged from legitimate primitives.

## Affected components

- Agent runtime and tool-invocation layer
- Tool authorization infrastructure
- Downstream data systems
- Audit and review systems
- Agent reasoning that selects tool sequences

## Traditional controls and why insufficient

| Traditional control | Why insufficient |
|---|---|
| Per-tool authorization | Each tool call is correctly authorized; composition is unconstrained |
| API rate limiting | Limits volume per tool but does not prevent composition across tools at low individual rates |
| Bulk-export controls | Triggered by single high-volume calls, not by patterns of small individual calls |
| Network egress monitoring | Blind to internal tool composition |
| Tool-level audit logging | Captures individual events; pattern detection across the chain requires correlation logic that most enterprises lack |

## Recommended controls

| Control | Role |
|---|---|
| CTL-003 (Action verification at high-impact boundaries) | Primary: requires verification when composed actions exceed thresholds, even if no single action does |
| CTL-005 (End-to-end audit and accountability) | Primary: enables detection and forensic review of composition patterns |
| CTL-001 (Identity and authorization context propagation) | Secondary: limits blast radius when chains cross authorization boundaries |

## Control gap flag

CTL-003 was designed for individual high-impact actions, not for composed actions. Applying it here requires extending the verification model to recognize composed effects. This is a gap that may justify either a refinement of CTL-003 or a new control around action composition governance.

## Regulatory hooks

| Regulation | Article or section | Relevance |
|---|---|---|
| EU AI Act | Art. 9 (Risk management) | Composed agent actions are a risk class that risk management must explicitly address |
| EU AI Act | Art. 14 (Human oversight) | Composition that exceeds individual review thresholds defeats the oversight model |
| DORA | Art. 6 to 8 (ICT risk management) | Operational resilience requires controls on agent action composition for financial entities |
| GDPR | Art. 5(1)(c) (Data minimization) | Aggregating individual data points into composites can violate minimization even when each retrieval is permitted |
| GDPR | Art. 25 (Data protection by design) | Design must consider composed effects, not only individual operations |

## Residual risk

Even with CTL-003 extended to composed actions and CTL-005 providing detection, residual risk remains because (a) defining the composition threshold is context-dependent and hard to automate, (b) sophisticated chains may stay below any threshold while still causing harm, and (c) human review at composition boundaries adds latency that organizations resist. Human-in-the-loop at composition checkpoints for high-stakes contexts is the only fully reliable mitigation.

## Detection and mitigation maturity

Detection: experimental. Mitigation: emerging.
