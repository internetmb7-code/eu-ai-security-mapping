# AGT-005: Audit and Provenance Failure

**Status**: Compressed draft. Schema-faithful but lighter detail than AGT-001 and AGT-002. Realistic example to be populated.

**Primary surface**: Audit and provenance
**Secondary surfaces**: Tool-use, Memory and persistence

## Description

Agent actions cannot be reliably attributed to the originating user, the specific instructions that triggered them, the data that informed them, or the reasoning that selected them. Traditional audit captures events; agents require richer provenance because their actions are emergent products of context, retrieved data, instructions, and model reasoning. When this provenance is incomplete, organizations cannot answer fundamental accountability questions: who caused this, what data influenced it, was it authorized, and is it reproducible.

Sub-patterns include user attribution loss (agent actions logged to the agent's identity rather than the originating user), context provenance loss (the data that influenced an agent decision is not preserved with the decision record), reasoning opacity (the model's selection of tools or content is not auditable), and persistence boundary loss (state changes to memory or vector stores are not linked to the user or context that caused them).

## Attack scenario

A regulator investigating a customer complaint at a regulated DACH financial services enterprise asks the institution to produce, for a specific customer interaction six months ago: which user initiated the interaction, what data the agent retrieved, what was returned to the user, and why the agent took the specific actions it took. The institution can produce a log of the agent's tool calls but cannot link them to the originating user with confidence (CTL-001 was implemented inconsistently), cannot reconstruct the retrieved data context (the source documents have been updated since), and cannot explain why the model selected specific tools (no reasoning provenance was captured). The institution faces enforcement risk under GDPR Article 5(2) accountability and DORA Article 12 incident reporting obligations.

## Affected components

- Logging infrastructure
- Agent runtime telemetry
- Model invocation records
- Retrieval system snapshots
- Identity and session correlation
- Vector-store change tracking

## Traditional controls and why insufficient

| Traditional control | Why insufficient |
|---|---|
| Application audit logging | Captures agent's actions but not reasoning or context |
| SIEM correlation | Effective for known patterns; agent actions produce novel patterns the SIEM is not configured for |
| Identity and session logging | User attribution requires user-context propagation through the agent (CTL-001), which may be inconsistent |
| Document version history | Captures changes to documents but not which agent retrievals saw which version |
| Tool-call logging | Captures calls but not the model's reasoning that produced them |

## Recommended controls

| Control | Role |
|---|---|
| CTL-005 (End-to-end audit and accountability) | Primary: directly addresses the threat |
| CTL-001 (Identity and authorization context propagation) | Primary: prerequisite for clean user attribution |
| CTL-002 (Tool-output and context provenance) | Primary: provides the context-provenance dimension |

## Control gap flag

CTL-005 covers audit at a high level but the specific dimensions (user attribution, context provenance, reasoning provenance, persistence boundary) might benefit from being explicit in v2. For v1, the consolidation under CTL-005 is acceptable.

## ATLAS mapping

No direct technique; ATLAS focuses on attacker actions rather than defender capability gaps. Some agentic techniques touch on log obfuscation.

## Residual risk

Even with CTL-005 fully implemented, model reasoning provenance is fundamentally hard. Current LLMs do not produce reliable, deterministic explanations of their own decisions. Organizations should treat model decisions as partially opaque and design oversight assuming this constraint.

## Detection and mitigation maturity

Detection: established (for traditional logs); experimental (for reasoning provenance). Mitigation: emerging.

## Exemplar role

Illustrates the audit and provenance attack surface, specifically the pattern of agent actions becoming inattributable to originating users, instructions, or reasoning. Exemplifies how traditional audit captures events without the richer provenance that agent accountability requires.
